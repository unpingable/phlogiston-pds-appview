# Production secret custody

This is a custody map, not secret material and not activation authority.

| Material | Owner / consumer | Scope and generation | Storage and modes | Rotation / revocation | Backup |
|---|---|---|---|---|---|
| Browser session token and CSRF token | Phlogiston web | 32 random bytes each, issued only after OAuth callback; eight-hour local session | Token exists only in the secure cookie; hashed lookup key and session record under `/var/lib/phlogiston/web-sessions`, directory `0700`, files `0600` | logout deletes the server record; expiry makes it unusable | excluded; users re-enroll |
| OAuth state, DPoP and refresh/session material | pinned `@atproto/oauth-client-node` in Phlogiston web | generated by the library during a separately authorized enrollment; scope is exactly `atproto` | `/var/lib/phlogiston/oauth`, service-owned `0700` / `0600` | disconnect calls the OAuth session sign-out path and removes local use | excluded; users re-enroll |
| PDS PLC/signing/admin secrets | future independent Phlogiston PDS | generated on the production host by the selected pinned PDS procedure | separate PDS-only owner-readable environment/key files | PDS-specific deliberate rotation/revocation | required in encrypted authoritative PDS backup |
| communityd PDS credential | community authority operator / `communityd` only | generated only after the authority identity exists; bounded to the enrolled PDS writer | owner-only credential file referenced by `COMMUNITYD_CREDENTIAL_FILE`; never browser-visible | revoke at PDS and replace the reference | required only in private recovery escrow, never public evidence |
| Backup backend access | off-host backup operator | existing local Docker NFS volume; no credential is copied into Phlogiston | retained by the existing backup operator/runtime | existing NAS/client procedure | not copied into application backup |
| TLS private key | existing Caddy ACME storage | generated and renewed by Caddy after the route is installed | existing Caddy data volume and permissions | ACME/Caddy renewal and route removal | governed by existing Caddy recovery, not application archives |

There is no static Phlogiston cookie-signing or HMAC secret in the current
implementation. Browser tokens are opaque random values with server-side
records. `/admin/` is deliberately absent from the production artifact, so
there is no production admin-browser secret in this tranche.

Before deployment, an operator creates a non-secret
`phlogiston.secret-custody.v1` receipt from the example only after checking the
runtime owner and modes. PDS and communityd secrets are later activation
inputs; their absence must not be papered over by placeholder values.
