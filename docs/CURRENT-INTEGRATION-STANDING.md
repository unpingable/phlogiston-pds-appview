# Phlogiston current integration standing

## Current initial-integration standing (2026-10-03)

The September qualification below is historical evidence. The accepted forward
build now contains all eight community wheels and the community-live source,
static assets, frozen lockfile and closed offline dependency store: 7,010
manifest entries, artifact SHA-256
`1e040e276d9fa62ec64c68bf862ddfd94fb0c914c8889d3e6876bbe13a11f208`.
Runtime source is community `6436e6a30a8db6b65160c4d290c8764c4216651d`,
builder `f8bbf3319f65a7f7774490539274d965b1c7c50e`; later documentation commits
are not runtime changes. Packaging and isolated installed-artifact qualification
are accepted; host activation remains held.

Current holds are the prepared Q2 assertion/authority and Lexicon authority
records, a consenting second human maintainer/participant (also moderator if consenting,
otherwise a separately consenting moderator) and notification room.
Credential enrollment follows the selected identities mechanically. An external
cohort trial is a separate later intent, not required for the current
owner-authorized submit → admit → render integration.

Phlogiston has zero real users, no irreplaceable user repository state and no
current PDS continuity promise. Host-loss reconstruction from retained source,
configuration, appropriately held credentials/enrollment records and small
operational state is the current requirement. Existing restore rehearsals are
useful hardening. Total-site-loss recovery is outside the current envelope;
geographic/off-site recovery-key custody is not a launch gate. User-data/PDS DR
becomes a future requirement if user state is hosted or durability is promised.

Juche is non-normative for Phlogiston's operational posture, user commitments,
production classification and durability requirements; it is an implementation
reference only.
